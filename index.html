need clearer boundaries.

Keep raw keys out of agent code

Give each key a smaller blast radius

BUILT AROUND PRACTICAL CONTROLS

Security you can reason about.

Clear boundaries, visible decisions and fast response when something changes.

Least privilege, enforced

Bind a key to its project, environment, provider and supported actions. Unlisted sensitive actions default to deny or approval.

Secrets stay server-side

Provider credentials are stored encrypted with access restricted to the gateway. They do not appear in logs, agent context or normal UI after setup.

Human review for high impact

Pause actions such as external emails, bulk exports or production changes until an authorised person approves the exact request.

Fast revocation, clear audit

Disable keys, agents or integrations. Follow request IDs through safe event records that explain decisions without exposing credentials.

A virtual key is still a credential. Keep it in a server-side secret manager—not a browser bundle or public mobile app. Scopes, expiry and revocation reduce risk; no gateway can promise that an agent will never be compromised.
